# System Admin Live Workflows Implementation Plan

> Execution: native, sequential in the existing worktree. Use executing-plans after plan review. No delegation or Git mutations. Every task includes its own red/green verification.

**Goal:** Replace System Admin fixtures with privacy-scoped persistent workflows and enforce Inactive tenants across DB and API.

**Architecture:** Verified Supabase identity → Django platform endpoints → narrow user-JWT RPC. Private platform metadata and audit; business membership remains separate. OTP delivery is a recoverable side effect after atomic provisioning.

**Tech Stack:** Existing Django, Supabase/Postgres 17, React 19/Vite, JavaScript, oxlint, Vitest; no new packages.

**Spec:** ../specs/2026-11-20-system-admin-live-workflows.md (user approved in conversation).

## Global constraints

- Worktree .tmp/publish-dat; baseline 171f973. Keep all existing changes.
- Backend/local DB exception approved. Hosted still requires separate approval.
- Inactive locks tenant, including pre-issued JWTs. Never delete Auth users to suspend a company.
- System Admin never gains business membership or roster/PII access.
- accountEmail means invited MM; Gmail allowed, slug unique, domain reusable.
- No .env edits, secret output, password changes to existing demo users, hosted emails, commits, pushes or resets of existing stacks.
- New migration filenames generated with pinned Supabase CLI, not guessed. No edits to applied migrations.

## Review focus

1. An RPC using SECURITY DEFINER bypasses an otherwise-correct Inactive RLS guard: task 3 inventories and negatively tests every affected RPC.
2. Concurrent retry with same request UUID and different payload: task 2 must reject mismatch, not return another company's success.
3. Auth email sent but HTTP acknowledgement lost: task 4 tracks attempts and prevents unsafe user/password compensation.
4. Search result shrinks or prior fetch finishes after a newer one: task 5 tests page clamp and ignores stale responses.
5. React success while Auth/profile or DB/email is only partly saved: tasks 4/6 assert distinct partial-failure messages and retained edits.
